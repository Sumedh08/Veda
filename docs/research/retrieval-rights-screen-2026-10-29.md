# Retrieval routes and access-rights screen

**Research date:** 2026-10-29  
**Status:** Source/code review complete for the retrieval routes present in this checkout. Official arXiv robots, license, reuse, and API-terms pages were inspected; no full-text document was requested or downloaded. This is an engineering screen, not legal advice.

## Scope and repository evidence

The supported full-text route currently begins with an OpenAlex work record. `backend/app/providers/openalex.py` requests `open_access` and `best_oa_location` and preserves those objects as provider metadata. Crossref is used for bibliographic discovery and a bounded abstract excerpt; `backend/app/providers/crossref.py` selects DOI, bibliographic fields, abstract, and type, but does not select Crossref `link` or `license` fields or fetch a document. No Crossref TDM endpoint or publisher-host-specific adapter is implemented.

In `backend/app/research/workflow.py`, full-text retrieval is considered only for an OpenAlex source's `best_oa_location`. The workflow requires `is_oa is True` and accepts only the lower-cased location license identifiers `cc0`, `public-domain`, and `cc-by`. It first attempts `landing_page_url` as HTML. If HTML was not successfully retrieved, it can attempt `pdf_url` under the same OpenAlex OA/license gate. The fetchers independently enforce the same license allowlist in `backend/app/research/safe_fetch.py` and `safe_pdf.py`. Thus both HTML and PDF routes are implemented; the earlier HTML-only description in `docs/research/retrieval-safety-decision.md` is stale with respect to PDF fallback.

The fetchers accept any hostname in a discovered URL, including redirect destinations that pass the transport checks. They do not contain a host allowlist or publisher/repository policy registry. They accept HTTP and HTTPS starts; redirects are bounded, manually followed, DNS-resolved and public-address checked at each hop, and an HTTPS start may not downgrade to HTTP. The user agent identifies Veda. There is no `robots.txt` retrieval, parser, cache, terms-of-service check, or host-specific permission check in either fetch path. Existing tests exercise license gates and transport protections with fixtures; this review did not run tests or live retrieval.

## Authoritative source findings

### Robots is a crawler signal, not a rights grant

IETF [RFC 9309, Robots Exclusion Protocol](https://www.rfc-editor.org/rfc/rfc9309.html) (Standards Track, September 2022) says its rules are requested crawler-access rules and expressly says they are not access authorization. A crawler that receives a parseable `robots.txt` must follow parseable rules. Under the RFC, an HTTP 4xx response makes the file “unavailable” and a crawler *may* access resources; an HTTP 5xx or network failure makes it “unreachable” and the crawler must assume complete disallow. The RFC recommends not using cached rules for more than 24 hours unless the file is unreachable. These protocol outcomes do not establish copyright permission, a license, or compliance with a site's separate terms.

**Engineering interpretation:** Veda should check the actual destination origin before requesting each HTML/PDF document, including every redirect origin, use a descriptive stable user-agent token, and honor matching disallow rules. For a conservative Veda policy, inability to obtain or safely parse the policy should deny the document even where RFC 9309 permits a crawler to proceed after a 4xx “unavailable” result. A robots allow result still must not satisfy the independent license/rights gate.

### OpenAlex fields identify an OA copy; they do not grant its copyright

OpenAlex's first-party [Open Access help page](https://help.openalex.org/data/works/open-access/) describes OA status and copy/location fields; its [license vocabulary](https://help.openalex.org/data/licenses/) treats license as a property of a particular location and includes explicit unknown/catch-all categories such as `other-oa` and `publisher-specific-oa`. These are metadata fields, not a host policy check. OpenAlex's [Fulltext product documentation](https://help.openalex.org/access/fulltext/) says cached PDFs retain original copyright and OpenAlex grants no additional rights, and directs users to `best_oa_location.license` to inspect the work's reported license. The documentation was last updated 2026-10-26.

Veda does **not** currently use the OpenAlex `content.openalex.org` download route; it follows the external `best_oa_location.landing_page_url` or `.pdf_url`. The OpenAlex full-text API is a distinct provider route with metered downloads, so switching to it would require a separate budget-aware integration; it is not a free/reuse-rights shortcut. The OpenAlex [API reference](https://help.openalex.org/api/) describes OpenAlex's own dataset as CC0, but that does not relicense third-party article full text exposed by a location.

The existing allowlist is materially narrower than “open access”: good. It still trusts a mutable provider field without checking the license notice on the destination document or a license URL/provenance. OpenAlex itself says its full-text PDFs keep their original copyright, so `is_oa: true` alone cannot justify reuse. A stale or erroneous location license may cause a false acceptance.

The identifier `public-domain` needs deliberate normalization. OpenAlex's vocabulary labels this as public domain/CC0, but Creative Commons distinguishes its [CC0 dedication](https://creativecommons.org/public-domain/)—a legal tool to waive rights—from the [Public Domain Mark](https://creativecommons.org/public-domain/pdm/), which is an informational label for a work believed to be public domain. Preserve the raw source identifier and its provenance; do not treat any unverified natural-language “public domain” string or mark as equivalent to a rights-holder's CC0 dedication. For `cc-by`, the [CC BY 4.0 legal code](https://creativecommons.org/licenses/by/4.0/legalcode) permits reproduction, sharing, and adaptations subject to conditions including attribution, a license link, and indicating changes where relevant. Veda should retain enough creator/license/source information to meet attribution conditions when it presents or redistributes material.

OpenAlex's [Terms of Service PDF](https://openalex.org/OpenAlex_termsofservice.pdf), last revised 2026-10-02, says the database aggregates information from external platforms and prohibits uses that infringe third-party intellectual-property rights or impose unreasonable load. These service terms govern use of OpenAlex; they do not replace the external host's access rules or grant rights in hosted articles.

### Crossref provides metadata and license signals, not blanket full-text rights

Crossref's first-party [REST API documentation](https://www.crossref.org/documentation/retrieve-metadata/rest-api) says its public API exposes deposited scholarly metadata and that almost none of that metadata is subject to copyright and may be used for any purpose. That statement covers Crossref metadata; it is not permission to retrieve the articles described by the metadata. Crossref's [license metadata best practices](https://www.crossref.org/documentation/principles-practices/best-practices/license) explain that license metadata can indicate TDM permissions/conditions and explicitly warn that Crossref checks that supplied values are URLs but does not verify that they resolve to an active license. Veda's current Crossref adapter does not use those license/full-text links. No specific publisher or repository policy is applicable across the present route because source hosts are unrestricted and are discovered per work; reviewing a particular host without a real selected URL would invent coverage.

### Candidate host screen: arXiv

The official [`arxiv.org/robots.txt`](https://arxiv.org/robots.txt) observed on 2026-10-29 allows `/pdf` and `/abs` under its wildcard group, but includes `Crawl-delay: 15` and says indiscriminate automated downloads are not permitted. T-50 now implements a shared database-backed host interval scheduler and bounded defer when the slot cannot fit. That engineering change is not a positive go-ahead for arXiv: the rights, version, storage/display, bandwidth and supported bulk-interface questions below still prevent enabling the host.

arXiv's first-party [API terms](https://info.arxiv.org/help/api/tou.html) say content may be retrieved, stored and used for personal or research purposes, but e-prints cannot be stored and served from a user's servers unless the holder's permission or the submitted license permits it. They state the vast majority use arXiv's non-exclusive distribution license, and separately limit legacy API requests to one every three seconds per all machines under a user's control. The [bulk-access guide](https://info.arxiv.org/help/bulk_data.html) recommends `export.arxiv.org` for harvesting and calls out rights-holder permissions for redistributing content. The [arXiv license page](https://info.arxiv.org/help/license/index.html) describes per-submission CC BY 4.0 and CC0 choices while distinguishing the default non-exclusive license; the [reuse FAQ](https://info.arxiv.org/help/license/reuse.html) says rights vary by assigned license and version.

**Decision:** do not add `arxiv.org` to the host registry. The generic OpenAlex license assertion is not enough to determine per-version rights or attribution; the terms distinguish research use from serving content; indiscriminate download is discouraged; and the guide prefers a separate bulk interface for harvesting. A future arXiv adapter would need per-version license metadata, a permitted storage/passage display policy, and a reviewed, rate-limited supported retrieval route. This is a bounded candidate screen, not a legal conclusion.

### Candidate host screen: PLOS journals

PLOS's first-party [Terms of Use](https://plos.org/terms-of-use/) (last updated 2026-10-05) says PLOS articles and accompanying materials are licensed by their authors for use/distribution under CC BY or a comparable permissive license, subject to citation of the original source. Its [content-license page](https://journals.plos.org/plosone/s/licenses-and-copyright) says PLOS journals apply CC BY unless otherwise noted, and permits reuse subject to attribution. The terms also prohibit excessive bandwidth or unreasonable burden when using PLOS APIs. These are relevant host/reuse signals but do not validate an OpenAlex location value for an individual work or resolve any separately owned third-party figures/materials.

A read-only GET of [`https://journals.plos.org/robots.txt`](https://journals.plos.org/robots.txt) on 2026-10-29 returned HTTP 200 text/plain and `Crawl-delay: 30`, along with search, metrics, and user-path disallows. T-50 now has local shared-slot coverage for positive delays; PostgreSQL execution and live host behavior are still unverified. **Decision:** do not add `journals.plos.org` to the registry until a specific host/license review and database-backed limiter verification support it. No article URL or full-text content was fetched as part of this screen.

## Recommendation for implementation

1. Keep three independent gates in the retrieval workflow: (a) source-level reuse evidence and permitted license scope; (b) destination-origin access policy, including robots and any known site terms; and (c) transport/media/parser security. Record each outcome separately in retrieval metadata so “robots allowed” cannot be displayed as “licensed,” and “OA” cannot be displayed as “reuse permission verified.”
2. Resolve an exact reviewed host policy for the actual start URL, each redirect destination, and robots redirects. Use the exact `VedaResearch` user-agent product token in requests and robots matching. Apply parseable `Allow`/`Disallow` rules per RFC 9309, obey rule precedence, bound and cache robots fetches, and enforce the effective host/robots delay using shared database slots. Fail closed on unavailable/invalid policy or a slot that does not fit the step deadline. Never use robots permission as a license substitute.
3. Require auditable license provenance: persist raw OpenAlex location fields, provider and retrieval time; where feasible corroborate against the destination's license URI/notice and match the license version. Deny unknown, conflicting, stale/unavailable, publisher-specific, or unsupported license assertions. Treat the `public-domain` alias as a provider identifier with documented semantics, not a universal natural-language classification. Keep CC BY attribution and license links attached to extracted passages/reports.
4. Either maintain a reviewed allowlist of source hosts with documented retrieval terms or implement per-host terms evidence/exception policy. If terms cannot be established for a host, do not fetch. A robots check alone cannot answer that rights question.
5. Add deterministic tests for robots parsing/matching and cache behavior, 4xx vs 5xx/network outcomes, same-origin and cross-origin redirects, per-hop policy checks, robots/license mismatch, metadata missing/conflict cases, license attribution persistence, and assurance that Crossref discovery does not accidentally activate a full-text route. No full-text or live provider retrieval is claimed by this note.

## Implementation result (T-42)

The fetchers now require a document-license identifier, an exact recent host-policy entry, and an allowing robots rule independently. The host registry has no enabled entries; all current live HTML/PDF routes therefore fail before DNS. Each redirect requires a separate host review. `cc0` and `cc-by` remain eligible identifiers; `public-domain` is denied until its per-work rights meaning is corroborated. Robots files are bounded at 512 KiB, follow at most five safe redirects, and cache successful rules for no more than 24 hours. Non-200, malformed, oversized, unreachable or disallowed rules fail closed. Positive `Crawl-delay` is now scheduled through shared database origin slots; a slot that cannot fit the retrieval deadline is deferred without sending the document request. The host registry remains empty pending rights review, and PostgreSQL runtime behavior is still unverified.

The source inspector now distinguishes the provider's license assertion, host-terms policy ID/link, robots status, and safe denial code. Fixture tests cover route policy, robots parsing/precedence/redirect behavior, unavailable/invalid/delayed policy, each HTML/PDF redirect host, exact-host scope, stale/invalid registry, and metadata display. An arXiv primary-source screen was recorded but arXiv was not enabled: its robots policy has a 15-second delay and its terms require attention to the per-version license and serving/storage use. No full text was downloaded. See [ADR-0005](../architecture/ADR-0005-retrieval-host-policy.md) and [`retrieval-safety-decision.md`](retrieval-safety-decision.md).

## External gaps and unknowns

- No full-text source was fetched. arXiv and PLOS were screened as candidate hosts but neither is enabled because current crawler-delay requirements cannot be met; other dynamically discovered OpenAlex hosts still lack terms and license-corroboration review.
- OpenAlex's license field is a metadata assertion and the app does not verify it against a source-host license declaration; field accuracy and freshness remain external unknowns.
- The generic allowlist is not a determination that every text extraction, storage, quotation, model submission, or report use satisfies every license condition, other right, jurisdiction, or site term.
- Crossref's TDM links/license metadata are not implemented in the current adapter and were not used to justify retrieval.
- No full text was requested or downloaded; no paid or metered API call was made.
