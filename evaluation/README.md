# Evaluation workflow

- `questions/ai_economics_cases.json` contains 36 draft research questions. All are unreviewed; primary-source searches are pending, `gold_answer` is null, and no performance score is implied.
- `rubrics/research-quality.md` defines the expert-review dimensions and scoring scale.
- `benchmark-plan.json` pre-registers seven purposively selected cases, source-inclusion rules, run capture, a two-reviewer protocol, metrics/denominators, and explicit interpretation limits. The selected sample is not representative. Candidate identities, versions, access paths and source-stated reuse terms have a bounded metadata screen in [`../docs/research/benchmark-source-version-rights-audit-2026-10-29.md`](../docs/research/benchmark-source-version-rights-audit-2026-10-29.md). Candidate mappings are still not a gold answer or a reviewer-validated final source set; Noy–Zhang's final article access/terms and the use-specific status of CC BY-NC material remain unresolved.
- `schemas/annotation-record.schema.json` defines one independent human review of one immutable run. Completed records require run-manifest hash, provider/model/version, date, reviewer pseudonym/role/expertise/conflict declaration, all rubric dimensions, score rationales, and N/A explanations. Do not add a reviewer's direct identity to repository records.
- `annotations/schema-only-example.json` only demonstrates the schema. It has null run and reviewer metadata, no scores, `review_status: not_reviewed`, and is explicitly excluded from human-review denominators.
- Store real records in `annotations/records/` as separate immutable files, one per reviewer and case-run. Preserve original reviews; adjudication does not overwrite them. Keep any pseudonym-to-identity map outside this repository.
- Run `python scripts/validate_evaluation_registry.py` to check registry structure, count, case status, and absence of invented gold answers. This validates metadata only; it does not measure research quality.
- Run `python scripts/validate_benchmark_plan.py` to check fixed sample references and the plan's non-scoring state.
- Run `python scripts/validate_annotation_records.py` to validate schema and record invariants. It does not authenticate reviewers or verify that an annotation happened.
- Run `python scripts/evaluate_fixtures.py` to exercise passage-support, citation-link, material-claim coverage, scope coverage, scope-safe relationship, disjoint-hypothesis, and budget-compliance metric calculations on synthetic fixtures. The runner deliberately reports no scientific quality score and does not load or grade the draft registry cases.
- Deterministic source-to-report behavior is exercised by `backend/tests/test_workflow.py` with mocked scholarly records and a local test database. That is an implementation invariant check, not a benchmark of economic accuracy.
- Current blockers: case-specific content review and independent gold-source validation remain incomplete; Noy–Zhang's final Science version/full text/terms could not be verified in this environment; the CC BY-NC source requires a Veda-specific noncommercial-use determination or permission; no complete Veda benchmark run exists; the OpenRouter credential previously posted in conversation must be revoked/rotated before a live request; and two qualified independent reviewers have not been engaged. Do not use that exposed credential. No quality result may be claimed until the blockers are addressed with actual artifacts.
- Before claiming research quality, freeze the reviewer-validated source set, run the selected queries with recorded provider/model versions and provider-reported cost, inspect citations and passages independently, publish exclusions/denominators/disagreements, and record observed results in `RESULTS.md`.
