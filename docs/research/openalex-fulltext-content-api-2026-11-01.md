# OpenAlex archived full-text availability and content access

**Checked:** 2026-11-01  
**Sources:** OpenAlex official Help Center only  
**Live API calls:** None. This is documentation review, not an account or network integration test.

## Findings that affect Veda

- OpenAlex Work API records can report `has_content` format booleans for cached `pdf` and `grobid_xml` representations. The API-only `content_urls` field contains download URLs under `content.openalex.org`; clients can construct the content endpoint from the Work ID. `has_content` is distinct from `has_fulltext`, which describes searchable text and does not guarantee a downloadable file.
- A content file download is metered at **$0.01 per file** under the currently published pricing. OpenAlex documents a `HEAD` request as free, but Veda does not issue one in this implementation. The Work metadata lookup and a subsequent content-file download are separate operations.
- OpenAlex explicitly says it does not add rights to cached material; original copyright and work-specific licensing continue to apply. `has_content=true` and a public content URL are availability metadata, not permission to download, retain, display, or redistribute the work.
- OpenAlex's TEI output is generated by GROBID and may contain structural or metadata errors. Document shapes differ across GROBID versions; some TEI uses a lowercase `<tei>` root and places `<div>` nodes directly under `<text>`. GROBID does not OCR scanned PDFs.

## Implementation decision

Veda now asks the bounded Works search for `has_content` and preserves only strict `pdf` / `grobid_xml` boolean values in versioned OpenAlex provider metadata. It does not request, persist, or follow `content_urls`. The source API and browser inspector expose those values as **archived-format availability only**, independent from the Veda retrieval status, rights decision, and evidence access class.

This change performs no content download, does not incur a content-file charge, and does not claim the indexed license is legally sufficient. Actual acquisition remains a separate bounded operation requiring an explicit rights decision, a cost reservation, safe endpoint validation, response-size limits, parser validation, and persisted retrieval provenance.
